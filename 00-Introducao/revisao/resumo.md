# Resumo — Módulo 00: Introdução

Uma página. Usado nas revisões D+30/D+90 dos capítulos deste módulo.

## O sistema (00.01)

O manual é um sistema que se **opera**, não um livro que se lê. Trilha linear (00→13, grafo de dependências), capítulos com 21 seções fixas, prática em 4 níveis (Aquecimento → Aplicação → Desafio → Mini projeto) com gabaritos separados e regra dos 15 minutos. Avanço por critério: CP1 (checklist do capítulo), CP2 (simulado do módulo, ≥8/10 + prático ≥3), CP3 (rubrica da entrega + ≥70% no simulado de fase). Ritmo: máx. 2 capítulos novos/dia, um capítulo aberto por vez, domingo é descanso.

## O território (00.02)

Três papéis: backend **serve** (APIs), engenharia de dados **transforma** (ETL/pipelines), DevOps mantém **rodando**. O banco de dados é o centro comum — SQL é inegociável. Engenharia ≠ ciência de dados (esteira ≠ análise). A trilha cobre backend + dados + operação essencial com uma única linguagem (Python) — e deixa fora frontend, mobile e ML. Vagas se leem separando coração de desejável.

## A oficina (00.03)

Três peças: interpretador Python ≥3.12 (executa), VS Code (edita, pré-visualiza, depura), Git (versiona). O PATH é a agenda de endereços do terminal: "não reconhecido" = problema de endereço, não de existência. Veredito objetivo de ambiente: `valida_ambiente.py` → APROVADO 4/4. Diagnóstico sempre da hipótese barata para a cara; ferramentas futuras só no módulo que as usa.

## A retenção (00.04)

Recuperar (puxar da memória, com esforço, em voz alta) fixa; reler só conforta. Gestos do ciclo: D+1 = 5 flashcards · D+7 = questões + reexplicar o 🧠 · D+30 = exercício transversal · D+90 = manutenção de código real. Ritual de fim de sessão (2–5 min): registrar → agendar → marcar feitos. Falha feia reinicia o item em D+1; fila >15 = reduzir ritmo; hiato se paga em blocos espaçados, nunca em maratona.

## O projeto (00.05)

Aurora Comércio: e-commerce fictício em crescimento caótico; você é a primeira pessoa de engenharia. Atlas: o sistema único que **evolui e nunca recomeça** — uma dor de negócio por módulo, entregas acumulativas, histórico Git como artefato de portfólio. Regras: instruções precisas de arquivos; refatoração só com commits explicativos; nunca exige conteúdo futuro; README honesto por fase. Mora em `13-Projetos/atlas/` — fundado com `git init` (caixa-preta até 02.08–02.09).
